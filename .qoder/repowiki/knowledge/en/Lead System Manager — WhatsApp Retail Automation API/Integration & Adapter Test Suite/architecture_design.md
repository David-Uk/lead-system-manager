Test files under `tests/` are flat per feature (`health.test.js`, `whatsappAdapter.test.js`, `simulate.test.js`, `seed.test.js`, `webhook.test.js`, `errors.test.js`) and share a `helpers/` directory of reusable bootstraps. `helpers/setup-env.mjs` is imported first in every test to pin `process.env` values (NODE_ENV=test, WHATSAPP_MODE=simulated, LLM_PROVIDER=none, etc.) before any `src/` module loads, relying on ESM static-import ordering so dotenv never overrides them. `helpers/testDb.js` wraps `mongodb-memory-server` + Mongoose to spin up a per-file in-memory Mongo instance with `startTestDb`/`stopTestDb` lifecycle hooks and a `clearDb()` helper that empties all collections between tests. The WhatsApp adapter tests use a special isolation pattern: `run-adapter-scenario.mjs` is executed as a separate Node process via `child_process.execFile`, allowing it to override `globalThis.fetch` and environment variables without polluting the parent test runner; the parent parses the last JSON line of stdout for assertions. `test_inputs/webhook-sample.json` provides fixture payloads consumed by webhook-related tests.
